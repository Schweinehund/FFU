# Milestone v1.11.0: Readiness Dashboard & Optional Hyper-V

**Status:** SHIPPED 2026-02-06
**Phases:** 45-48
**Total Plans:** 16

## Overview

Transform FFU Builder's Home tab from placeholder text into a live pre-flight readiness dashboard, making Hyper-V optional when VMware is selected. The journey begins with formalizing in-flight DISM resilience patterns, establishes the dashboard UI infrastructure with auto-run validation on launch, adds conditional hypervisor logic with one-click auto-remediation, and concludes with config-aware revalidation for dynamic prerequisite checking.

## Phases

### Phase 45: DISM Resilience Formalization

**Goal**: Build pipeline validates DISM health before all image operations and detects degradation early to prevent cascading failures.
**Depends on**: Nothing (first phase)
**Plans**: 3 plans

Plans:
- [x] 45-01: Debug mode infrastructure + DISM startup gate in BuildFFUVM.ps1
- [x] 45-02: Harden post-KB checks (hard stop) in FFU.Updates + add missing DISM checks in FFU.Media
- [x] 45-03: Version bumps, Pester tests, changelog, and verify-app

**Requirements**: DISM-01, DISM-02, DISM-03

**Success Criteria**:
1. Build pipeline calls Test-DismReady before every Mount-WindowsImage and Add-WindowsPackage operation
2. Build pipeline calls Test-DismFunctional after each KB install to detect service degradation
3. Build pipeline skips non-critical DISM operations (WinSxS cleanup) when WIMMount service is broken
4. All DISM operations log clear actionable errors when validation fails
5. User sees "DISM service unavailable" messages instead of cryptic 0x800704db errors

## Milestone Summary

**Key Decisions:**
- Pipe-delimited message format for dashboard (structured data within FFU.Messaging strings)
- Separate dashboardPollTimer from build pollTimer (independent operation)
- Critical/non-critical check gating (block build on critical, confirm on warnings)
- Scriptblock handlers with GetNewClosure() for scope capture
- Cancel-and-restart for hypervisor changes (stop in-progress job before new check run)
- Export button disabled during export to prevent race conditions
- Static mapping for hypervisor-dependent checks (1 Hyper-V, 5 VMware, 14 independent)

**Issues Resolved:**
- Home tab was placeholder text with no functionality
- Hyper-V was required even when VMware was selected
- No way to fix pre-flight failures without manual PowerShell commands
- No indication of config staleness after hypervisor change
- No way to export diagnostics for support scenarios

**Issues Deferred:**
- Check result persistence across app sessions (DASH-F01)
- Step-by-step remediation wizard (DASH-F02)
- Check history timeline (DASH-F03)
- Per-check refresh buttons (DASH-F04)

**Technical Debt Incurred:**
- None significant — clean implementation with full test coverage
