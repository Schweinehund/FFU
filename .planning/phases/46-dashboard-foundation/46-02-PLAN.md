  <files>FFUDevelopment/FFUUI.Core/FFUUI.Core.Dashboard.psm1</files>
  <action>
Create a new file `FFUUI.Core.Dashboard.psm1` in the FFUUI.Core directory. Follow the established pattern of other FFUUI.Core.*.psm1 files (synopsis, description, functions, Export-ModuleMember).

Include these functions:

**1. Get-CheckCategory**
Maps FFU.Preflight check names to dashboard categories. Returns one of: 'System', 'Hypervisor', 'BuildTools', 'Network', 'Optimization'.

Category mapping (derived from FFU.Preflight tier structure):
- System: Administrator, PowerShellVersion, VMResources, ScratchSpace
- Hypervisor: HyperV, VmxToolkit, VMwareDrivers, VMwareBridgeConfiguration, HyperVSwitchConflict
- BuildTools: ADK, WimMount, DiskSpace, DISMState, DISMCleanup
- Network: Network, HostIPAddress
- Optimization: AntivirusExclusions, ConfigurationFile

If check name not found in map, default to 'System'. Accept [string]$CheckName parameter.

**2. Update-DashboardCheckUI**
Parameters: [PSCustomObject]$State, [string]$CheckName, [string]$Status, [string]$Severity, [string]$Message, [string]$Remediation

Determines the category via Get-CheckCategory, finds the correct panel (`$State.Controls."pnl${category}Checks"`).

Creates a StackPanel for the check item containing:
- Outer StackPanel (vertical) for check line + optional remediation
- Inner StackPanel (horizontal, Margin "0,3") for status icon + check name + brief message
  - Status icon TextBlock (FontSize 14, Margin "0,0,8,0"):
    - Passed: text "✓" (checkmark), Foreground "#2E7D32" (dark green)
    - Failed + Critical: text "✗" (X mark), Foreground "#C62828" (dark red)
    - Failed + Warning: text "⚠" (warning), Foreground "#F57F17" (dark amber)
    - Warning: text "⚠", Foreground "#F57F17"
    - Skipped: text "○" (empty circle), Foreground "Gray"
    - Running: text "◌" (dotted circle), Foreground "#1565C0" (blue)
  - Check name TextBlock: Text is human-readable version of check name (e.g., "Administrator" -> "Administrator Privileges"). Use a simple lookup hashtable for friendly names.
  - Brief message TextBlock: Text is $Message, Foreground Gray, MaxWidth 500, TextTrimming CharacterEllipsis

- If Status is 'Failed' and Severity is 'Critical', auto-add an Expander below the check line:
  - Header: "Remediation Steps" in bold
  - Content: TextBlock with $Remediation text, TextWrapping Wrap, FontFamily Consolas, Background "#FFF3F3" (light red tint), Padding 8
  - IsExpanded = $true (auto-expand critical failures)

- If Status is 'Failed' and Severity is 'Warning', add similar Expander but IsExpanded = $false

Add the outer StackPanel to the category panel's Children collection.

**3. Update-CategorySummary**
Parameters: [PSCustomObject]$State, [string]$Category

Counts checks in the category panel (`$State.Controls."pnl${category}Checks".Children`). Scans child elements to count passed (green icon), failed (red icon), warning (amber icon) items.

Rather than scanning, accept counts: [int]$TotalChecks, [int]$PassedChecks, [int]$FailedChecks, [int]$WarningChecks

Updates the category icon TextBlock (`$State.Controls."txt${Category}Icon"`) and summary TextBlock (`$State.Controls."txt${Category}Summary"`):
- All passed: icon "✓" green (#2E7D32), summary "({Passed}/{Total})" green
- Any failed: icon "✗" red (#C62828), summary "({Passed}/{Total} -- {Failed} failed)" red
- Warnings only: icon "⚠" amber (#F57F17), summary "({Passed}/{Total} -- {Warning} warnings)" dark orange
- No checks run yet: icon "○" gray, summary "(checking...)" gray italic

**4. Update-SummaryStatus**
Parameters: [PSCustomObject]$State, [int]$CriticalCount, [int]$WarningCount, [int]$TotalChecks, [int]$PassedChecks

Updates the summary banner (`borderSummaryStatus` background and `txtSummaryStatus` text):
- All passed (Critical=0, Warning=0): Background "#E8F5E9" (light green), Text "Ready to Build -- All {Total} checks passed", Foreground "#2E7D32"
- Critical failures: Background "#FFEBEE" (light red), Text "{Critical} Critical Issue(s), {Warning} Warning(s)", Foreground "#C62828"
- Warnings only: Background "#FFF8E1" (light amber), Text "Ready to Build -- {Warning} Warning(s)", Foreground "#F57F17"

**5. Update-BuildButtonState**
Parameters: [PSCustomObject]$State, [int]$CriticalCount, [int]$WarningCount

Updates Build button state:
- If CriticalCount > 0: `$State.Controls.btnRun.IsEnabled = $false`, set ToolTip to "{CriticalCount} critical issue(s) must be resolved before building"
- If WarningCount > 0 (no critical): `$State.Controls.btnRun.IsEnabled = $true`, set ToolTip to "{WarningCount} warning(s) detected. Build will prompt for confirmation."
  - Store `$State.Data.dashboardWarningCount = $WarningCount` for the build click handler to check
- If all passed: `$State.Controls.btnRun.IsEnabled = $true`, ToolTip = "Start FFU build"
  - Clear `$State.Data.dashboardWarningCount = 0`

Do NOT modify the existing btnRun click handler here. That wiring happens in Plan 03.

**6. Clear-DashboardResults**
Parameters: [PSCustomObject]$State

Clears all check items from all 5 category panels (`pnl{Category}Checks.Children.Clear()`).
Resets all category icons to "○" gray and summaries to "(checking...)" gray italic.
Resets summary banner to "Checking system readiness..." with LightGray background.
Does NOT touch build button state (that's reset separately).

End file with `Export-ModuleMember -Function Get-CheckCategory, Update-DashboardCheckUI, Update-CategorySummary, Update-SummaryStatus, Update-BuildButtonState, Clear-DashboardResults`

Follow PowerShell style: [CmdletBinding()], [OutputType()], OTBS brace style, 4-space indentation. Add proper .SYNOPSIS and .DESCRIPTION to each function.
