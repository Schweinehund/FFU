  <name>Task 1: Create Test-ProviderSwitch Validation Function</name>
  <files>
    FFUDevelopment/Modules/FFU.Hypervisor/Public/Test-ProviderSwitch.ps1
  </files>
  <action>
Create a new public function `Test-ProviderSwitch` that validates provider switching scenarios.

Function signature:
```powershell
function Test-ProviderSwitch {
    [CmdletBinding()]
    [OutputType([hashtable])]
    param(
        [Parameter(Mandatory = $true)]
        [ValidateSet('HyperV', 'VMware')]
        [string]$FromProvider,

        [Parameter(Mandatory = $true)]
        [ValidateSet('HyperV', 'VMware')]
        [string]$ToProvider,

        [Parameter(Mandatory = $false)]
        [VMConfiguration]$Config,

        [Parameter(Mandatory = $false)]
        [string]$VMNamePattern = '_FFU*'
    )
}
```

Implementation:
1. Return hashtable with:
   - `CanSwitch`: boolean
   - `Warnings`: array of warning messages
   - `Blockers`: array of blocking issues
   - `OrphanedVMs`: array of VM names/paths from FromProvider
   - `IncompatibleConfig`: boolean with reason if config incompatible
   - `RecommendedActions`: array of suggested actions

2. Orphan detection:
   - If FromProvider is HyperV, check for VMs matching VMNamePattern using Get-VM
   - If FromProvider is VMware, search for VMX files in common locations matching pattern
   - Report running VMs as blockers, stopped VMs as warnings

3. Config compatibility check (if Config provided):
   - Check DiskFormat compatibility:
     - VHDX only works with Hyper-V (blocker if switching to VMware)
     - VMDK only works with VMware (blocker if switching to Hyper-V)
     - VHD works with both (no issue)
   - Check EnableTPM:
     - Warn if switching to VMware with TPM enabled (VMware TPM requires encryption)
   - Check disk file exists and is accessible

4. Provider availability:
   - Verify ToProvider is available (use GetAvailabilityDetails from 16-01)
   - Include remediation if not available

5. Log all checks performed for transparency.
  </action>
  <verify>
```powershell
# Test function exists and returns expected structure

$result.Keys | Should -Contain 'CanSwitch'
$result.Keys | Should -Contain 'OrphanedVMs'
$result.Keys | Should -Contain 'Blockers'
```
  </verify>
  <done>
Test-ProviderSwitch function exists and returns comprehensive validation results including orphan detection and config compatibility.
  </done>

Add provider switch awareness to Get-HypervisorProvider.

1. Add module-scope variable to track previously returned provider:
   ```powershell
   # At module level (in psm1 or top of file)
   $script:PreviousProviderType = $null
   ```

2. Add `-ValidateSwitch` parameter to Get-HypervisorProvider:
   - When specified, validates switch from previous provider to requested provider
   - Logs warnings from Test-ProviderSwitch
   - Throws on blockers (unless -Force is also specified)

3. Add `-Force` parameter:
   - When combined with -ValidateSwitch, proceeds despite blockers
   - Logs: "Proceeding with provider switch despite blockers: $blockerList"

4. Update the function to track provider type:
   ```powershell
   # Before returning provider
   $script:PreviousProviderType = $provider.Name
   ```

5. Add informational logging when switching providers:
   - "Switching hypervisor from $PreviousProviderType to $($provider.Name)"
   - Only log if previous provider was different

6. Add helper function `Get-PreviousHypervisorType`:
   - Returns $script:PreviousProviderType
   - Useful for callers to check current state
