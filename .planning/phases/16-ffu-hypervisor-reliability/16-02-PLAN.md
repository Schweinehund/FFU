  <name>Task 1: Add Transient State Detection Helper</name>
  <files>
    FFUDevelopment/Modules/FFU.Hypervisor/Classes/VMInfo.ps1
  </files>
  <action>
Add a static helper method to VMInfo class for transient state detection.

1. Add static method `[bool] IsTransientState([VMState]$state)`:
   ```powershell
   static [bool] IsTransientState([VMState]$state) {
       $transientStates = @(
           [VMState]::Starting,
           [VMState]::Stopping,
           [VMState]::Saving,
           [VMState]::Restoring
       )
       return $state -in $transientStates
   }
   ```

2. Add static method `[VMState] GetExpectedStableState([VMState]$transientState)`:
   - Starting -> Running
   - Stopping -> Off
   - Saving -> Saved
   - Restoring -> Running
   - Returns input state if not transient

3. Add instance method `[bool] IsInTransientState()`:
   - Returns `[VMInfo]::IsTransientState($this.State)`

4. Update the VMState enum documentation in comments to clarify which states are transient.

Do NOT change the VMState enum values themselves - maintain backward compatibility.
  </action>
  <verify>
```powershell
[VMInfo]::IsTransientState([VMState]::Starting) | Should -BeTrue
[VMInfo]::IsTransientState([VMState]::Running) | Should -BeFalse
[VMInfo]::GetExpectedStableState([VMState]::Starting) | Should -Be ([VMState]::Running)
```
  </verify>
  <done>
VMInfo class has static helpers for transient state detection and expected stable state mapping.
  </done>

<task type="auto">
  <name>Task 2: Enhance Provider GetVMState with Stabilization Option</name>
  <files>
    FFUDevelopment/Modules/FFU.Hypervisor/Providers/HyperVProvider.ps1
    FFUDevelopment/Modules/FFU.Hypervisor/Providers/VMwareProvider.ps1
  </files>
  <action>
Add optional stabilization behavior to GetVMState on both providers.

1. Add new method to IHypervisorProvider interface concept (add to both providers):
   ```powershell
   [VMState] GetVMStateStable([VMInfo]$VM, [int]$MaxWaitSeconds)
   ```

2. Implement in HyperVProvider:
   - Call GetVMState to get initial state
   - If state is transient (use VMInfo.IsTransientState), wait and retry
   - Poll every 500ms up to MaxWaitSeconds
   - Return stable state, or last known transient if timeout
   - Log: "VM '$Name' in transient state '$State', waiting for stable state..."

3. Implement in VMwareProvider:
   - Same pattern as Hyper-V
   - Use existing Get-VMwarePowerStateWithVmrun for state detection
   - Note: VMware states from vmrun are simpler (poweredon/poweredoff) but process detection can have timing

4. Update existing GetVMState to optionally log if transient state detected:
   - Add WriteLog: "GetVMState returned transient state '$State' - caller may want GetVMStateStable()"

5. Handle race condition in VMwareProvider specifically:
   - After vmrun start, there's a brief window where process may not be detected
   - GetVMState should NOT return Unknown during this window if called right after StartVM
   - Add check: if called within 5 seconds of this provider's last StartVM call, and process not found, wait 1 second and retry once
   - Track last start time with instance variable `$this.LastStartVMTime`
  </action>
  <verify>
```powershell

# GetVMStateStable should return non-transient state
$methods = $provider | Get-Member -MemberType Method
$methods.Name | Should -Contain 'GetVMStateStable'
```
  </verify>
  <done>
Both providers have GetVMStateStable method that waits for non-transient states. GetVMState logs when returning transient state.
  </done>

Enhance Wait-VMStateChange and VMware state functions to handle transient states gracefully.

   - Add parameter `-AllowTransient` (default $false)

   - Example: If waiting for 'Off' and VM is in 'Stopping', keep waiting
   - Add informational logging: "VM '$VMName' transitioning through '$currentState' toward '$TargetState'"
   - Update the "check VM state directly" defense block to use IsTransientState

2. Update Get-VMwarePowerStateWithVmrun in Invoke-VMwareRestMethod.ps1:
   - Add return value metadata to indicate if detection was ambiguous
   - Return hashtable instead of string for internal use:
     ```powershell
     return @{
         State = 'poweredon'  # or 'poweredoff'
         Confidence = 'High'  # 'High', 'Medium', 'Low'
         Method = 'process'   # Which detection method succeeded
     }
     ```
   - Keep string return for backward compatibility by adding overload or checking caller
   - Actually, simpler: add optional `-Detailed` parameter, default returns string (backward compatible)

3. Update VMwareProvider.GetVMState to use the detailed info when available:

   - If confidence is 'Low', consider state as potentially transient
