<objective>
Port CORRECT-02 (`04dfb5f`): add `Get-EffectiveDriverWindowsRelease` and inject a dedicated `$driverWindowsRelease` at both driver-dispatch sites so OEM driver downloads for LTSC builds (2016/2019/2021/2024) receive the base Windows release (10/11) instead of the LTSC year.

Purpose: A user can download OEM drivers for an LTSC build without the driver step failing on a release-year validation error — `[int]$WindowsRelease = 2021`/`2024` currently yields HP `Win2021`/`Win2024`, Lenovo `_Win2021`/`_Win2024`, and Dell's `else -> W22` default, all wrong. The fix gates the remap on `$isLTSC` (Server years untouched) and never mutates the load-bearing global `$WindowsRelease`.
