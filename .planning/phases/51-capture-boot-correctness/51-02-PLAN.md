<objective>
Port CORRECT-03 (`6c0ee8a`): write boot files with the ADK's `bcdboot.exe` (arch-aware) instead of the host's, hard-fail the build if the ADK bcdboot cannot be located, and add an early ADK-bcdboot existence check to the FFU.Preflight ADK validation.

Purpose: Captured images must boot on Secure Boot 2023-cert hardware. The bcdboot binary version determines which cert variant lands on the ESP; the host bcdboot can silently stage 2023-signed boot files that boot in the Hyper-V VM but fail on fleet hardware lacking the 2023 cert. This is a silent, deploy-time, high-blast-radius failure — the code must hard-fail loudly rather than ship a maybe-unbootable image.

Output: Extended `Add-BootFiles` (FFU.Imaging.psm1) + updated call site (BuildFFUVM.ps1), new bcdboot check in `Test-FFUADK` (FFU.Preflight.psm1) + version bump (FFU.Preflight.psd1), and appended CORRECT-03 assertions in Test-Phase51Correctness.ps1.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build host -> ESP (boot files) | The bcdboot binary that stages boot files determines which Secure Boot cert variant lands on the system partition |
| ADK install path -> Add-BootFiles | $adkPath (registry-sourced, preflight-validated) selects the bcdboot binary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-51-03A | Tampering/Spoofing | Host bcdboot stages wrong-cert boot files (boots in VM, fails on 2023-cert fleet hardware) | mitigate | Add-BootFiles uses the ADK bcdboot exclusively and hard-fails if absent (D-09/D-11); no host fallback path exists — this is the core boot-trust fix. |
| T-51-03B | Denial of Service | Missing ADK bcdboot discovered deep in imaging wastes a full build | mitigate | Test-FFUADK preflight check fails early with -UpdateADK remediation (D-12); runtime throw is the backstop. |
| T-51-03C | Tampering | Path traversal / binary substitution via $AdkPath | accept | $adkPath comes from the registry KitsRoot10 (system-protected `C:\Program Files (x86)\Windows Kits\10\`), validated by Test-ADKPrerequisites; not user-controllable at runtime. |
| T-51-03D | Repudiation | Silent cert-variant drift on a future ADK bump | accept (logged) | ADK version is WriteLog'd at Add-BootFiles time (D-13); a future ADK upgrade is a conscious decision, captured in the build log. |
</threat_model>
