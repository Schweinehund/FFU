Add exponential backoff retry logic to OEM driver downloads (REL-DRV-01).

Purpose: Make OEM driver downloads resilient to transient network failures. Currently, Start-BitsTransferWithRetry provides basic retry with fixed delays. This adds exponential backoff with jitter to prevent thundering herd scenarios on service recovery.

Output: Invoke-DriverDownloadWithRetry wrapper function used by Get-DellDrivers, Get-HPDrivers, Get-LenovoDrivers, and Get-MicrosoftDrivers.

  <action>
    Create Invoke-DriverDownloadWithRetry function in FFU.Drivers.psm1. Follow the exponential backoff pattern from Invoke-CatalogQueryWithRetry in FFU.Updates.

    **Function signature:**
    ```powershell
    function Invoke-DriverDownloadWithRetry {
        [CmdletBinding()]
        [OutputType([void])]
        param(
            [Parameter(Mandatory)]
            [string]$Source,

            [Parameter(Mandatory)]
            [string]$Destination,

            [Parameter()]
            [string]$OperationName = 'Driver download',

            [Parameter()]
            [int]$MaxRetries = 3,

            [Parameter()]
            [int]$BaseDelaySeconds = 5
        )
    }
    ```

    **Implementation:**
    1. Loop from attempt 1 to MaxRetries
    2. Call Start-BitsTransferWithRetry in try/catch (leverages existing BITS fallback chain)
    3. On success, log completion and return
    4. On failure:
       - Log warning with attempt number, source URL, and error message
       - If not last attempt, calculate delay with exponential backoff + jitter
       - Jitter: `$jitter = Get-Random -Minimum 0 -Maximum 3`
       - Delay: `$delay = ($BaseDelaySeconds * [math]::Pow(2, $attempt - 1)) + $jitter`
       - Wait using Start-Sleep
    5. After all retries exhausted, log error and throw exception with context

    **Safe logging pattern for ThreadJob compatibility:**
    ```powershell
    if ($function:WriteLog) {
        WriteLog "WARNING: $warningMsg"
    }
    else {
        Write-Verbose "WARNING: $warningMsg"
    }
    ```

    **Do NOT export:** This is an internal helper function. Do not add to FunctionsToExport.
    Place the function near the top of the module, after the using statement and before Get-MicrosoftDrivers.
  </action>

  </verify>
