**3. Add isLoadingConfig guard.** Find where `Update-UIFromConfig` is called (search for `Update-UIFromConfig -ConfigContent`). Wrap the call site with the loading flag:

```powershell
$State.Flags.isLoadingConfig = $true
try {
    Update-UIFromConfig -ConfigContent $configContent -State $State
} finally {
    $State.Flags.isLoadingConfig = $false
}
```

This guard is checked by `Invoke-USBArtifactScan` (added in Plan 01) to prevent premature scanning during config load. After the flag is cleared, the scan triggered by `rbUSBMode.IsChecked = $true` inside Update-UIFromConfig will proceed naturally because it fires synchronously before the flag is cleared -- so the guard must NOT be inside Update-UIFromConfig itself, but around the CALLER of Update-UIFromConfig. Actually -- re-read the flow: if `rbUSBMode.IsChecked = $true` fires the Checked event synchronously INSIDE Update-UIFromConfig, the scan will see `isLoadingConfig = $true` and skip. Then after `isLoadingConfig = $false`, no automatic re-trigger happens. The fix: after clearing the flag, if ActiveMode was USBMode, explicitly call `Invoke-USBArtifactScan -State $State`:

```powershell
$State.Flags.isLoadingConfig = $true
try {
    Update-UIFromConfig -ConfigContent $configContent -State $State
} finally {
    $State.Flags.isLoadingConfig = $false
}
# If USB Mode was restored, fire initial scan now that config is fully loaded
if ($null -ne $State.Controls.rbUSBMode -and $State.Controls.rbUSBMode.IsChecked) {
    Invoke-USBArtifactScan -State $State
}
```

Find ALL call sites of `Update-UIFromConfig` and apply this pattern.
