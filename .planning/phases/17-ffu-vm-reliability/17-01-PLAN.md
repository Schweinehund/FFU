  <name>Task 1: Add Get-VMCreationDiagnostics function</name>
  <files>FFUDevelopment/Modules/FFU.VM/FFU.VM.psm1</files>
  <action>
Add a new function `Get-VMCreationDiagnostics` that analyzes VM creation failures and returns actionable guidance.

Function parameters:
- `[string]$ErrorMessage` - The exception message from the failed operation
- `[string]$FailedStep` - Which step failed (CreateVM, ConfigureProcessor, MountISO, ConfigureTPM, StartVM)
- `[string]$VMName` - Name of the VM being created
- `[string]$VMPath` - Path where VM was being created (optional)

Function should:
1. Pattern-match common errors:
   - "already exists" -> "A VM with this name already exists. Remove it with: Remove-VM -Name {VMName} -Force"
   - "insufficient memory" -> "Not enough memory available. Close applications or reduce VM memory allocation."
   - "cannot find path" -> "Path does not exist: {path}. Create directory or verify path."
   - "access denied" -> "Access denied. Run as Administrator or check folder permissions."
   - "Hyper-V not enabled" -> "Hyper-V is not available. Enable with: Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V -All"
   - "HGS" / "guardian" errors -> "TPM configuration failed. This is non-critical - VM can work without TPM."

2. Return a PSCustomObject with properties:
   - `ErrorType`: Classified error type (AlreadyExists, InsufficientResources, PathNotFound, AccessDenied, HypervisorNotAvailable, TPMConfiguration, Unknown)
   - `FailedStep`: Which step failed
   - `OriginalError`: The original error message
   - `Remediation`: Actionable guidance string
   - `IsCritical`: Boolean - false for TPM errors, true for others
   - `ResourcesCreated`: Array of resources that may need cleanup

3. Log diagnostics via WriteLog before returning

Add to Export-ModuleMember and FunctionsToExport in .psd1.
  </action>
  <verify>
Function exists: `Get-Command Get-VMCreationDiagnostics -Module FFU.VM`
Import module: `Import-Module FFUDevelopment\Modules\FFU.VM -Force`
  </verify>

<task type="auto">
  <name>Task 2: Update New-FFUVM with cleanup registration</name>
  <files>FFUDevelopment/Modules/FFU.VM/FFU.VM.psm1</files>
  <action>
Update `New-FFUVM` function to register cleanup actions progressively using FFU.Core's Register-CleanupAction pattern.

Changes to make:
1. After successful `New-VM`, immediately register VM cleanup:
   ```powershell
   $vmCleanupId = Register-VMCleanup -VMName $VMName
   WriteLog "Registered VM cleanup action: $vmCleanupId"
   ```

2. After successful HGS Guardian creation, register guardian cleanup:
   ```powershell
   $guardianCleanupId = Register-CleanupAction -Name "Remove HGS Guardian: $VMName" -ResourceType 'HGS' -ResourceId $VMName -Action {
       Remove-HgsGuardian -Name $using:VMName -ErrorAction SilentlyContinue
       Get-ChildItem 'Cert:\LocalMachine\Shielded VM Local Certificates\' -Recurse |
           Where-Object { $_.Subject -like "*$using:VMName*" } |
           Remove-Item -Force -ErrorAction SilentlyContinue
   }.GetNewClosure()
   ```

3. In the catch block, before re-throwing:
   - Call `Get-VMCreationDiagnostics` to get classified error
   - Log the diagnostics output
   - Log which resources will be cleaned up
   - Existing cleanup code can stay (it's good fallback for when cleanup registration wasn't reached)

4. On successful completion (after Start-VM), unregister cleanups:
   ```powershell
   Unregister-CleanupAction -CleanupId $vmCleanupId -ErrorAction SilentlyContinue
   Unregister-CleanupAction -CleanupId $guardianCleanupId -ErrorAction SilentlyContinue
   WriteLog "VM creation successful - cleanup handlers unregistered"
   ```

5. Track which step we're on for diagnostics:
   ```powershell
   $currentStep = 'CreateVM'
   # ... after successful creation
   $currentStep = 'ConfigureProcessor'
   # etc.
   ```
  </action>

- $currentStep tracked throughout
- Get-VMCreationDiagnostics called in catch block

  </verify>
  <done>New-FFUVM registers cleanup at each step and uses diagnostics function on failure</done>
