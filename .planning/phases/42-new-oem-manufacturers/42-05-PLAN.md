**Function 1: `Get-FujitsuDriversModelList`**

```powershell
function Get-FujitsuDriversModelList {
    [CmdletBinding()]
    param(
        [Parameter(Mandatory = $true)]
        [string]$ModelSearchTerm,
        [Parameter(Mandatory = $true)]
        [hashtable]$Headers,
        [Parameter(Mandatory = $true)]
        [string]$UserAgent
    )
```

**Logic:**
1. Create `$models = [System.Collections.Generic.List[PSCustomObject]]::new()`
2. Log: `WriteLog "Querying Fujitsu support portal for model: $ModelSearchTerm"`
3. Construct the Fujitsu support search URL. Use the Fujitsu global support search endpoint:
   - Primary URL: `https://support.ts.fujitsu.com/IndexSearch.asp?lng=COM&CT=1&ESSION=1&ESSION=1&ProductSearch=$([uri]::EscapeDataString($ModelSearchTerm))`
   - This searches Fujitsu's global support portal for matching products
4. Wrap the web request in try/catch:
   - Suppress verbose output during web request (same pattern as Lenovo: save `$VerbosePreference`, set to `'SilentlyContinue'`, restore after)
   - Use `Invoke-WebRequest -Uri $url -UseBasicParsing -Headers $Headers -UserAgent $UserAgent -ErrorAction Stop`
5. Parse the HTML response to extract model names and product IDs:
   - Look for product listing patterns in the HTML response. Fujitsu support pages typically list products with links containing product identifiers.
   - Use regex to find model entries: `<a[^>]+href="[^"]*ProductName=([^"&]+)[^"]*"[^>]*>([^<]+)</a>` or similar patterns that match product links.
   - For each match, extract the product name and product ID (URL parameter).
   - **IMPORTANT:** If the HTML structure is not parseable or the search returns no results, fall back to a static LIFEBOOK/STYLISTIC model list (see fallback below).
6. For each discovered model:
   ```powershell
   $models.Add([PSCustomObject]@{
       Make  = 'Fujitsu'
       Model = $modelName.Trim()
       Link  = $productPageUrl   # Full URL to the product's driver download page
   })
   ```
7. Log: `WriteLog "Found $($models.Count) Fujitsu models matching '$ModelSearchTerm'."`

**Fallback — Static known-models list:**
If the web request fails OR returns zero parseable results, fall back to a curated static list of common Fujitsu enterprise models that match the search term:

```powershell
$knownModels = @(
    'LIFEBOOK U7412', 'LIFEBOOK U7512', 'LIFEBOOK U7612',

    'LIFEBOOK A3510', 'LIFEBOOK A3511',
    'LIFEBOOK U7311', 'LIFEBOOK U7411', 'LIFEBOOK U7511',
    'LIFEBOOK U9311', 'LIFEBOOK U9311X',
    'LIFEBOOK E5411', 'LIFEBOOK E5511',
    'STYLISTIC Q7312', 'STYLISTIC Q5010',
    'LIFEBOOK U7413', 'LIFEBOOK U7513',
    'LIFEBOOK E5413', 'LIFEBOOK E5513'
)
$filtered = $knownModels | Where-Object { $_ -like "*$ModelSearchTerm*" }
```
Log: `WriteLog "WARNING: Fujitsu portal search failed or returned no results. Using static model list ($($filtered.Count) matches)."`

For each filtered static model, construct a PSCustomObject with Make='Fujitsu', Model=$modelName, Link=$null (Save-FujitsuDriversTask will construct the URL from the model name).

8. Return `$models`

**Catch block:** Log the error with `WriteLog "Error querying Fujitsu support portal: $($_.Exception.Message)"` and fall through to the static fallback. Do NOT throw — return empty list or static fallback results gracefully.

**Function 2: `Save-FujitsuDriversTask`**

```powershell
function Save-FujitsuDriversTask {
    [CmdletBinding()]
    param(
        [Parameter(Mandatory = $true)]
        [PSCustomObject]$DriverItemData,
        [Parameter(Mandatory = $true)]
        [string]$DriversFolder,
        [Parameter(Mandatory = $true)]
        [int]$WindowsRelease,
        [Parameter(Mandatory = $true)]
        [hashtable]$Headers,
        [Parameter(Mandatory = $true)]
        [string]$UserAgent,
        [Parameter()]
        [System.Collections.Concurrent.ConcurrentQueue[hashtable]]$ProgressQueue = $null,
        [Parameter()]
        [bool]$CompressToWim = $false,
        [Parameter()]
        [bool]$PreserveSourceOnCompress = $false
    )
```

**Logic (follow Lenovo Save-LenovoDriversTask pattern closely):**

1. Extract identifier: `$identifier = $DriverItemData.Model`, `$make = "Fujitsu"`
2. Sanitize: `$sanitizedIdentifier = ConvertTo-SafeName -Name $identifier`
3. Set up paths:
   - `$makeDriversPath = Join-Path -Path $DriversFolder -ChildPath $make`
   - `$modelPath = Join-Path -Path $makeDriversPath -ChildPath $sanitizedIdentifier`
   - `$driverRelativePath = Join-Path -Path $make -ChildPath $sanitizedIdentifier`
   - `$tempDownloadPath = Join-Path -Path $makeDriversPath -ChildPath "_TEMP_Fujitsu_$($sanitizedIdentifier)_$($PID)"`

4. Check for existing drivers using `Test-ExistingDriver` (same pattern as Lenovo lines 206-237). Handle the `$CompressToWim` case for existing folders.

5. Ensure directories exist.

6. **Determine driver download URL:**
   - If `$DriverItemData.Link` is not null/empty, navigate to that page and parse for direct download links.
   - If `$DriverItemData.Link` is null (static fallback), construct a search URL from the model name:
     `$searchUrl = "https://support.ts.fujitsu.com/IndexDownload.asp?lng=COM&CT=1&LNG=EN&ProductSearch=$([uri]::EscapeDataString($identifier))&OSC=WIN&OSV=$WindowsRelease"`
   - Parse the download page HTML to find driver pack links (look for `.exe` and `.zip` download links).
   - Prefer a single "driver pack" or "SCCM pack" link if available. Otherwise, collect individual driver download links.

7. **Download each driver file:**
   - Use `Start-BitsTransferWithRetry` for each download (same as Lenovo pattern).
   - Report progress via `$ProgressQueue` using `Invoke-ProgressUpdate`.

8. **Extract based on file extension:**
   ```powershell
   if ($driverFile -like '*.zip') {
       # ZIP extraction
       WriteLog "Extracting ZIP: $driverFilePath to $extractFolder"
       Expand-Archive -Path $driverFilePath -DestinationPath $extractFolder -Force
   }
   elseif ($driverFile -like '*.exe') {
       # EXE silent extraction — try /extract first, fall back to /s /e
       WriteLog "Extracting EXE: $driverFilePath to $extractFolder"
       try {
           $extractArgs = "/extract `"$extractFolder`""
           Invoke-Process -FilePath $driverFilePath -ArgumentList $extractArgs -Wait $true | Out-Null
       }
       catch {
           WriteLog "WARNING: /extract failed for $driverFile, trying /s /e flag..."
           try {
               $extractArgs = "/s /e=`"$extractFolder`""
               Invoke-Process -FilePath $driverFilePath -ArgumentList $extractArgs -Wait $true | Out-Null
           }
           catch {
               WriteLog "WARNING: EXE extraction failed for $driverFile. Skipping. Error: $($_.Exception.Message)"
               continue
           }
       }
   }
   else {
       WriteLog "WARNING: Unknown file format '$driverFile'. Skipping."
       continue
   }
   ```
   **Important:** Use a temporary extraction path (like Lenovo) to avoid long path issues. Move results to final destination after extraction.

9. **Post-extraction cleanup:** Delete downloaded installer files after successful extraction (same as Lenovo pattern).

10. **WIM compression:** If `$CompressToWim` is true, compress using `Compress-DriverFolderToWim` (identical to Lenovo lines 505-527).

11. **Cleanup and return:**
    - Remove temp download path in `finally` block.
    - Return `[PSCustomObject]@{ Identifier = $identifier; Status = $status; Success = $success; DriverPath = $driverRelativePath }`

**End of file:** `Export-ModuleMember -Function *`

**Key differences from Lenovo:**
- No PSREF API / JWT token needed — uses HTML scraping of Fujitsu support portal
- Mixed EXE/ZIP handling (Lenovo is EXE-only with extract commands from XML)
- No per-package XML catalog parsing — driver links come from the portal page directly
- Static fallback model list as safety net for portal changes

```powershell
function Get-FujitsuDrivers {
    <#
    .SYNOPSIS
    Downloads and extracts Fujitsu LIFEBOOK/STYLISTIC drivers for FFU builds

    .DESCRIPTION
    Searches the Fujitsu support portal for driver packages matching the specified
    model and Windows version, downloads them, and extracts the driver files.
    Handles mixed formats (EXE with /extract or /s /e flags, ZIP with Expand-Archive).
    Falls back to a static model list if the portal is unreachable.

    .PARAMETER Make
    OEM manufacturer name (should be "Fujitsu")

    .PARAMETER Model
    Fujitsu model name (e.g., "LIFEBOOK U7412", "STYLISTIC Q7312")

    .PARAMETER WindowsArch
    Windows architecture (x64, x86, or ARM64)

    .PARAMETER WindowsRelease
    Windows release version (10 or 11)

    .PARAMETER Headers
    HTTP headers for web requests

    .PARAMETER UserAgent
    User agent string for web requests

    .PARAMETER DriversFolder
    Root path where drivers should be downloaded and extracted

    .PARAMETER FFUDevelopmentPath
    Root FFUDevelopment path for download tracking

    .EXAMPLE
    Get-FujitsuDrivers -Make "Fujitsu" -Model "LIFEBOOK U7412" -WindowsArch "x64" `
                       -WindowsRelease 11 -Headers $Headers -UserAgent $UserAgent `
                       -DriversFolder "C:\FFU\Drivers" -FFUDevelopmentPath "C:\FFU"
    #>
    [CmdletBinding()]
    param (
        [Parameter(Mandatory = $true)]
        [string]$Make,

        [Parameter(Mandatory = $true)]
        [string]$Model,

        [Parameter(Mandatory = $true)]
        [ValidateSet("x64", "x86", "ARM64")]
        [string]$WindowsArch,

        [Parameter(Mandatory = $true)]
        [ValidateSet(10, 11)]
        [int]$WindowsRelease,

        [Parameter(Mandatory = $true)]
        [hashtable]$Headers,

        [Parameter(Mandatory = $true)]
        [string]$UserAgent,

        [Parameter(Mandatory = $true)]
        [string]$DriversFolder,

        [Parameter(Mandatory = $true)]
        [string]$FFUDevelopmentPath
    )
```

**Function body logic:**

1. **Setup paths:**
   ```powershell
   $makeDriversPath = Join-Path -Path $DriversFolder -ChildPath $Make
   $sanitizedModel = ($Model -replace '[\\\/\:\*\?\"\<\>\| ]', '_')
   $modelPath = Join-Path -Path $makeDriversPath -ChildPath $sanitizedModel
   ```

2. **Create directories:** Ensure `$makeDriversPath` and `$modelPath` exist.

3. **Log start:** `WriteLog "[Fujitsu][$Model][Download] Starting Fujitsu driver download for model: $Model (Windows $WindowsRelease $WindowsArch)"`

4. **Search Fujitsu support portal for driver packages:**
   - Construct URL: `$searchUrl = "https://support.ts.fujitsu.com/IndexDownload.asp?lng=COM&CT=1&LNG=EN&ProductSearch=$([uri]::EscapeDataString($Model))&OSC=WIN&OSV=$WindowsRelease"`
   - Wrap in try/catch with `Invoke-WebRequest`
   - Parse HTML response for download links (`.exe` and `.zip` driver files)
   - Use regex patterns to find download URLs in anchor tags

5. **Download and extract each driver package:**
   - For each download URL found:
     - Download using `Invoke-DriverDownloadWithRetry` (existing FFU.Drivers.psm1 function)
     - Check disk space using `Test-DriverDiskSpace` before extraction
     - Determine extraction method based on file extension:
       - `.zip`: `Expand-Archive -Path $filePath -DestinationPath $extractPath -Force`
       - `.exe`: Try `/extract "$extractPath"` first. If that fails, try `/s /e="$extractPath"`. Use `Get-DriverExtractionResult -Vendor 'Fujitsu'` to classify exit codes.
     - Log each extraction: `WriteLog "[Fujitsu][$Model][Extract] Extracted: $fileName"`

6. **Handle failures gracefully:**
   - If portal search returns no results: `WriteLog "[Fujitsu][$Model][Download] WARNING: No driver packages found on Fujitsu support portal for model '$Model' with Windows $WindowsRelease"`
   - If individual driver download fails: log WARNING and continue to next driver (graceful degradation, same as Dell/HP/Lenovo pattern)
   - If extraction fails for an EXE (both /extract and /s /e fail): `WriteLog "[Fujitsu][$Model][Extract] WARNING: EXE extraction failed for '$fileName'. This installer may not support silent extraction. Skipping."` and continue

7. **Verify extracted content exists:**
   ```powershell
   $extractedFiles = Get-ChildItem -Path $modelPath -Recurse -File
   if ($extractedFiles.Count -eq 0) {
       WriteLog "[Fujitsu][$Model][Download] WARNING: No driver files extracted for model '$Model'. The driver packages may not contain extractable drivers."
   } else {
       WriteLog "[Fujitsu][$Model][Download] Successfully extracted $($extractedFiles.Count) driver files for model '$Model'"
   }
   ```

8. **Do NOT use Get-Date** — use `[DateTime]::Now` for ThreadJob compatibility.

9. **Use structured logging prefixes:** All log messages should use `[Fujitsu][$Model][Operation]` format consistent with Phase 33 OEM logging standards (see FFU.Drivers.psd1 release notes for v1.4.0).
