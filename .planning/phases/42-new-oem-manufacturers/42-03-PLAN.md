**Function 1: `Get-PanasonicDriversModelList`**

Signature (matches HP pattern):
```powershell
function Get-PanasonicDriversModelList {
    [CmdletBinding()]
    param (
        [Parameter(Mandatory = $true)]
        [string]$DriversFolder,
        [Parameter(Mandatory = $true)]
        [string]$Make # Expected to be 'Panasonic'
    )
```

Logic -- primary path (SCCM catalog):
1. Compute paths: `$panasonicDriversFolder = Join-Path $DriversFolder $Make`, `$catalogCab = Join-Path $panasonicDriversFolder 'PanasonicSCCM.cab'`, `$catalogXml = Join-Path $panasonicDriversFolder 'PanasonicSCCM.xml'`
2. Ensure `$panasonicDriversFolder` exists (create if not)
3. Attempt to download the catalog CAB using `Get-CachedOEMCatalog`:
   - Vendor: `'Panasonic'` -- Plan 42-07 (infrastructure) MUST have already added 'Panasonic' to the ValidateSet. Since 42-03 depends on 42-07, this is guaranteed.
   - CatalogType: `'SCCM'`
   - PrimaryUrl: `[FFUConstants]::PANASONIC_CATALOG_URL` -- If this constant is empty string (catalog URL TBD), skip directly to the static fallback model list.
   - CachePath: `$catalogCab`
4. If download succeeds, extract CAB to XML: `Invoke-Process -FilePath 'expand.exe' -ArgumentList @($catalogCab, $catalogXml)`
5. Parse the XML to extract model list. The exact XML schema is TBD (needs validation during implementation). Expected SCCM catalog structure:
   ```xml
   <SystemsManagementCatalog>
     <SoftwareDistributionPackage>
       <Properties>
         <PublisherDisplayName>Panasonic</PublisherDisplayName>
       </Properties>
       <InstallableItem>
         <ApplicabilityRules>
           <IsInstallable>
             <And>
               <WmiQuery ... Result="..." />  <!-- Contains model info like CF-33, FZ-55 -->
             </And>
           </IsInstallable>
         </ApplicabilityRules>
       </InstallableItem>
     </SoftwareDistributionPackage>
   </SystemsManagementCatalog>
   ```
   **Implementation approach for XML parsing:** Since the exact schema is unknown until the catalog is actually fetched, implement a flexible parser:
   - First, try to find model information in `<SoftwareDistributionPackage>` elements
   - Look for model identifiers in `<WmiQuery>` elements, `<ProductName>` elements, or `Name` attributes
   - Extract unique model names (TOUGHBOOK CF-33, TOUGHBOOK FZ-55, TOUGHPAD FZ-G1, etc.)
   - If parsing yields 0 models (unexpected schema), fall back to static list
6. Build model list as `[System.Collections.Generic.List[PSCustomObject]]` with `Make` and `Model` properties (same schema as HP)
7. Sort alphabetically by Model and return

Logic -- fallback path (static model list):
If ANY of the following are true, fall back to the static model list:
- `[FFUConstants]::PANASONIC_CATALOG_URL` is empty or null
- Catalog download fails (catch block)
- CAB extraction fails
- XML parsing yields 0 models

Signature (matches HP Save-HPDriversTask pattern):
```powershell
function Save-PanasonicDriversTask {
    [CmdletBinding()]
    param (
        [Parameter(Mandatory = $true)]
        [PSCustomObject]$DriverItemData,
        [Parameter(Mandatory = $true)]
        [string]$DriversFolder,
        [Parameter(Mandatory = $true)]
        [ValidateSet("x64", "x86", "ARM64")]
        [string]$WindowsArch,
        [Parameter(Mandatory = $true)]
        [ValidateSet(10, 11)]
        [int]$WindowsRelease,
        [Parameter(Mandatory = $true)]
        [string]$WindowsVersion,
        [Parameter()]
        [System.Collections.Concurrent.ConcurrentQueue[hashtable]]$ProgressQueue = $null,
        [Parameter()]
        [bool]$CompressToWim = $false,
        [Parameter()]
        [bool]$PreserveSourceOnCompress = $false
    )
```

Logic (follow HP's Save-HPDriversTask as the template):
1. Extract `$modelName = $DriverItemData.Model`, `$make = $DriverItemData.Make`
2. Set `$identifier = $modelName`, sanitize with `ConvertTo-SafeName`
3. Set up folder paths: `$panasonicBaseFolder = Join-Path $DriversFolder $make`, `$modelSpecificFolder = Join-Path $panasonicBaseFolder $sanitizedModelName`
4. Check for existing drivers via `Test-ExistingDriver` (same as HP pattern lines 142-173)
5. If existing driver found, handle CompressToWim if needed (same as HP), return early
6. Re-parse the SCCM catalog XML (or use the static model list approach) to find the driver pack download URL for the selected model:
   - If catalog XML exists in `$panasonicBaseFolder`, parse it to find the driver pack URL matching the model and Windows version
   - The driver pack URL should be extracted from the catalog's `<ContentUri>` or `<OriginUri>` elements within the matching `<SoftwareDistributionPackage>`
   - If no catalog URL can be resolved for the model, log `WARNING: [Panasonic][$modelName][Download] No driver pack URL found in catalog. Manual driver download may be required.` and return a failure result
7. Download the driver pack CAB: `Start-BitsTransferWithRetry -Source $driverPackUrl -Destination $driverCabPath`
8. Extract the CAB using expand.exe: `Invoke-Process -FilePath 'expand.exe' -ArgumentList @($driverCabPath, '-F:*', $modelSpecificFolder)`
9. Clean up the downloaded CAB file after extraction
10. Handle CompressToWim if requested (same pattern as HP lines 401-415)
11. Return result PSCustomObject: `@{ Identifier = $identifier; Status = $finalStatus; Success = $successState; DriverPath = $driverRelativePath }`

Wrap in try/catch with the same error handling pattern as HP (lines 418-428): log error, set failure status, clean up partial folder.

Function signature (follows the Get-HPDrivers / Get-DellDrivers pattern exactly):
```powershell
function Get-PanasonicDrivers {
    <#
    .SYNOPSIS
    Downloads and extracts Panasonic TOUGHBOOK drivers for FFU builds

    .DESCRIPTION
    Downloads the Panasonic SCCM driver catalog, parses available TOUGHBOOK models,
    and extracts the appropriate driver packages for the specified model and Windows version.
    Uses Panasonic's SCCM CAB catalog for driver discovery. Falls back to CatalogPC-style
    direct download if SCCM catalog is unavailable.

    .PARAMETER Make
    OEM manufacturer name (expected: "Panasonic")

    .PARAMETER Model
    Panasonic model name (e.g., "TOUGHBOOK 55 (FZ-55)")

    .PARAMETER WindowsArch
    Windows architecture (x64, x86, or ARM64)

    .PARAMETER WindowsRelease
    Windows release version (10 or 11)

    .PARAMETER WindowsVersion
    Specific Windows version/build (e.g., "22H2", "23H2")

    .PARAMETER DriversFolder
    Root path where drivers should be downloaded and extracted

    .PARAMETER FFUDevelopmentPath
    Root FFUDevelopment path for download tracking

    .EXAMPLE
    Get-PanasonicDrivers -Make "Panasonic" -Model "TOUGHBOOK 55 (FZ-55)" -WindowsArch "x64" `
                         -WindowsRelease 11 -WindowsVersion "23H2" -DriversFolder "C:\FFU\Drivers" `
                         -FFUDevelopmentPath "C:\FFU"
    #>
    [CmdletBinding()]
    param (
        [Parameter(Mandatory = $true)]
        [string]$Make,

        [Parameter(Mandatory = $true)]
        [string]$Model,

        [Parameter(Mandatory = $true)]
        [ValidateSet("x64", "x86", "ARM64")]
        [string]$WindowsArch,

        [Parameter(Mandatory = $true)]
        [ValidateSet(10, 11)]
        [int]$WindowsRelease,

        [Parameter(Mandatory = $true)]
        [string]$WindowsVersion,

        [Parameter(Mandatory = $true)]
        [string]$DriversFolder,

        [Parameter(Mandatory = $true)]
        [string]$FFUDevelopmentPath
    )
```

Logic (follow the Get-HPDrivers pattern from FFU.Drivers.psm1 lines 1478-1597+):

1. Set up paths:
   ```powershell
   $DriversFolder = "$DriversFolder\$Make"
   $CatalogCab = "$DriversFolder\PanasonicSCCM.cab"
   $CatalogXml = "$DriversFolder\PanasonicSCCM.xml"
   ```
2. Create drivers folder if not exists
3. Disk space validation (REL-DRV-04): `Test-DriverDiskSpace -DriversFolder $DriversFolder -Vendor 'Panasonic' -EstimatedCompressedSizeMB 500` (Panasonic driver packs are smaller than Dell/HP, typically 200-500MB)
4. Download catalog using `Get-CachedOEMCatalog`:
   - Vendor: `'Panasonic'` (requires ValidateSet update from 42-07)
   - If `Get-CachedOEMCatalog` ValidateSet hasn't been updated yet, use `Invoke-DriverDownloadWithRetry` directly with manual cache check
   - CatalogType: `'SCCM'`
   - PrimaryUrl: `[FFUConstants]::PANASONIC_CATALOG_URL`
   - CachePath: `$CatalogCab`
5. If catalog URL is empty or download fails, log WARNING and throw with actionable message: `"Panasonic SCCM catalog unavailable. Visit Panasonic deployment tools portal to obtain drivers manually for model '$Model'."`
6. Extract CAB: `Invoke-Process -FilePath expand.exe -ArgumentList "$CatalogCab $CatalogXml"`
7. Parse catalog XML to find driver pack URL for the given Model and WindowsRelease/WindowsVersion combination
   - Search `<SoftwareDistributionPackage>` elements for model match
   - Extract driver pack download URL from matching package
   - If no match found for exact version, try fallback versions (same pattern as HP -- newest to oldest within same release, then other release)
8. Download driver pack CAB: `Invoke-DriverDownloadWithRetry -Source $driverPackUrl -Destination $driverPackCab -OperationName "Panasonic $Model driver pack"`
9. Extract driver pack: `Invoke-Process -FilePath expand.exe -ArgumentList "$driverPackCab -F:* $extractFolder"`
10. Log completion: `WriteLog "[Panasonic][$Model][Complete] Drivers extracted to $extractFolder"`
11. Clean up intermediate CAB files

Error handling: Wrap in try/catch. On failure, log with structured prefix `[Panasonic][$Model][Error]` and include actionable remediation (manual download URL, check network).
