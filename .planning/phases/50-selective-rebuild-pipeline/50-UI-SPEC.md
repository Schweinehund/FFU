All spacing values match the Phase 49 design contract. Phase 50 introduces zero new spacing values.

| Token | Value | WPF Margin/Padding syntax | Usage |
|-------|-------|--------------------------|-------|
| xs | 4px | `Margin="4"` or `Margin="0,0,0,4"` | Icon gaps, warning TextBlock bottom margin |
| sm | 8px | `Margin="8"` or `Margin="0,0,0,8"` | Inter-row spacing within a card |

## Typography

All font sizes match Phase 48/49 established values. Phase 50 introduces zero new font sizes.

**Declared scale: 4 sizes.**

| Role | Size | Weight | WPF LineHeight | Usage in Phase 50 |
|------|------|--------|----------------|-------------------|
| Tab section heading | 18px | Bold | default (~1.2) | Inherited — no new headings in Phase 50 |
| GroupBox section label | 16px | Bold | default | Inherited — no new GroupBoxes in Phase 50 |
| Artifact card title / ComboBox label | 13px | Bold (card label) / Normal (ComboBox) | default | Card label row: artifact name TextBlock is Bold 13px; ComboBox placed in same row uses 11px (matches metadata row size) |

## Interaction Contract

This section describes state machine transitions and interaction sequences required for Phase 50. Executor must implement exactly these behaviors.

### ComboBox Disposition Control — Per-Card Behavior

**XAML control name pattern:** `usb{Type}Disposition` where `{Type}` is one of: `FFU`, `DeployISO`, `Drivers`, `AppsISO`, `PPKG`, `Unattend`, `Autopilot`.

**Initial state (before scan):** All ComboBoxes `IsEnabled="False"`. Required-artifact ComboBoxes (FFU, DeployISO) are permanently `IsEnabled="False"`. All others enabled/disabled by scan result.

**Scan result → ComboBox enable rule:**

| Scan Status | ComboBox.IsEnabled | Default SelectedItem |
|-------------|-------------------|---------------------|
| Found | `True` | `Reuse` |
| Degraded | `True` | `Reuse` (warning TextBlock visible) |
| Error | `False` | `Skip` (optional) / `Reuse` (required — but IsReady gate blocks launch) |
| Missing | `False` | `Skip` (optional) / n/a (required — IsReady throw blocks launch before this matters) |

**SelectionChanged handler trigger:** `Add_SelectionChanged` on each ComboBox. Handler:
1. Returns immediately if `$State.Flags.isLoadingConfig` is `$true` (guard against Pitfall 3).
2. Returns immediately if `$e.AddedItems.Count -eq 0`.
3. Reads `$sender.SelectedItem.Tag` (the string "Reuse", "Rebuild", or "Skip").
4. Writes to `$State.Data.usbArtifactState['{Type}'].disposition`.

**Rebuild selected on Drivers card:** If Drivers `Rebuild` is selected and `$driversJsonPath` is not resolvable from config, no inline warning is shown at selection time — the failure is surfaced in the Monitor tab log during pipeline execution. (UI complexity is not warranted for this edge case; log messaging is sufficient per D-07.)

Source: D-01/D-02/D-03/D-10/D-11 (CONTEXT.md); 50-RESEARCH.md Pattern 1, Pitfall 3.

### Warning TextBlock — Degraded Artifact Display (D-11)

Each artifact card gains one additional row: a warning TextBlock initially `Visibility="Collapsed"`, made visible when `ArtifactStatus = Degraded`.

**Control name pattern:** `usb{Type}Warning`

**XAML for each card warning row:**
```xml
<TextBlock x:Name="usb{Type}Warning" Grid.Row="{last row + 1}"
           Text="" FontSize="11" Foreground="DarkOrange"
           Visibility="Collapsed" TextWrapping="Wrap"
           Margin="20,0,0,3"/>
```

**When scan returns Degraded:**
- Set `usb{Type}Warning.Text = $result.ErrorMessage` (or `$result.Warnings[0]` — whichever field ArtifactResult exposes; check `ArtifactScanner.Classes.ps1` `ArtifactResult.ErrorMessage`).
- Set `usb{Type}Warning.Visibility = 'Visible'`.
- Set status TextBlock: `Text = "Found (degraded)"` `Foreground = DarkOrange`.
- Enable the ComboBox (`IsEnabled = $true`) — user decides Reuse or Skip.
- Default ComboBox to `Reuse`.

**When scan returns any other status:** Set `usb{Type}Warning.Visibility = 'Collapsed'` and `usb{Type}Warning.Text = ""`.

Each artifact card gains one `<RowDefinition Height="Auto"/>` in its Grid to accommodate this row. For the FFU card, which also gains the helper text row, add two total new RowDefinitions.

Source: D-11 (CONTEXT.md); 50-RESEARCH.md F7; `ArtifactScanner.Classes.ps1` `ArtifactResult`.

### Config Persistence — Disposition Round-Trip

**On save (`Build-UIConfiguration`):** For each artifact, read `$State.Controls["usb{Type}Disposition"].SelectedItem.Tag` and write as `Disposition` string to `config.USBMode.Artifacts[{Type}].Disposition`. Remove the old `Include` boolean write entirely.

**On load (`Update-UIFromConfig`):** For each artifact, read `$entry.Disposition` string from config. Find the matching `ComboBoxItem` by `Tag` value and set `SelectedItem`. Guard with `$State.Flags.isLoadingConfig = $true` before and `$false` after to prevent SelectionChanged from firing during restore.

Source: 50-RESEARCH.md F2 (Config.psm1 patterns); D-01 (CONTEXT.md).

### Create USB Pre-Launch Validation (inherited — no changes to validation logic)

The existing three-gate validation from Phase 49 remains unchanged. The ComboBox replaces the CheckBox, so the validation gates must be updated to check the ComboBox state instead of CheckBox.IsChecked:

1. FFU must be Found/Found(user path): check `$State.Data.usbArtifactState.FFU.path` is non-null AND `usbFFUDisposition.SelectedItem.Tag` is `Reuse` (it always is — FFU is locked Reuse). The existing path/status check is sufficient; disposition cannot be Skip for required.
2. DeployISO: same logic as FFU.
3. At least one USB drive selected in `usbUSBDriveList`.

Source: Phase 49 UI-SPEC Interaction Contract (inherited).
