**A. Upgrade Get-PrivateProfileString in FFU.Core.psm1 with auto-growing buffer**

Find the function `Get-PrivateProfileString` (around line 268). Replace the fixed 1KB buffer implementation with an auto-growing buffer that starts at 1KB and doubles up to 64KB maximum. This is necessary because large INF files (especially SourceDisksFiles sections) can exceed 1KB.

Replace the current implementation (inside the try block, after the file existence check):
```powershell
$sbuilder = [System.Text.StringBuilder]::new(1024)
[void][Win32.Kernel32]::GetPrivateProfileString($SectionName, $KeyName, "", $sbuilder, $sbuilder.Capacity, $FileName)

$sbuilder.ToString()
```

With the auto-growing buffer pattern from 38-RESEARCH.md:
```powershell
$bufferSize = 1024          # Start with 1KB
$maxBufferSize = 65536      # Max 64KB
$sbuilder = $null
$charsCopied = 0

while ($true) {
    $sbuilder = [System.Text.StringBuilder]::new($bufferSize)
    $charsCopied = [Win32.Kernel32]::GetPrivateProfileString(
        $SectionName, $KeyName, "", $sbuilder, [uint32]$sbuilder.Capacity, $FileName)

    # If buffer was large enough (chars copied < capacity - 1), we're done
    if ([int]$charsCopied -lt ($sbuilder.Capacity - 1)) {
        break
    }

    # Double the buffer size and retry (up to max)
    if ($bufferSize -ge $maxBufferSize) {
        break
    }
    $bufferSize = [Math]::Min(($bufferSize * 2), $maxBufferSize)
}

$sbuilder.ToString()
```

Also update the function's .DESCRIPTION to mention auto-growing buffer:
