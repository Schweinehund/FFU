# Plan 44-01: DISM Resilience in FFU.Updates

## Goal

Close the Test-DismReady coverage gap in FFU.Updates so that mid-build WIMMount failures are detected instantly (via fltmc) and repaired or fast-failed, eliminating the 30+ minute hang that occurs when DISM operations are attempted against a broken WIMMount filter driver.

## Context

See `44-CONTEXT.md` for full gap analysis. The v1.9.8 fix implemented `Test-DismReady` in FFU.Core (fltmc-based, no DISM dependency) but only applied it to FFU.Imaging, FFU.VM, and BuildFFUVM.ps1 orchestrator points. The entire FFU.Updates module — which applies Windows updates and is the most DISM-intensive part of the build — was missed.

## Tasks

### Task 1: Add Test-DismReady gate to Add-WindowsPackageWithRetry (CRITICAL)

**File:** `FFUDevelopment/Modules/FFU.Updates/FFU.Updates.psm1`
**Location:** Function `Add-WindowsPackageWithRetry` (line 1481)

**Changes:**
1. At the top of the `while` loop (line 1524), BEFORE calling `Add-WindowsPackageWithUnattend`, add a `Test-DismReady` check:
   ```powershell
   # Verify WIMMount filter driver is loaded before attempting DISM operation
   # This uses fltmc.exe (instant, no DISM dependency) to detect mid-build WIMMount failures
   if (-not (Test-DismReady)) {
       WriteLog "WARNING: WIMMount filter driver is not loaded. Attempting auto-repair..."
       # Test-DismReady already attempts repair internally; check result
       if (-not (Test-DismReady)) {
           WriteLog "CRITICAL: WIMMount filter driver could not be restored"
           WriteLog "RESOLUTION: Reboot your computer and restart the FFU build process"
           WriteLog "A reboot will reload the WIMMount driver and reset DISM services"
           throw "WIMMount filter driver is not functional. DISM operations cannot proceed."
       }
       WriteLog "WIMMount filter driver restored successfully"
   }
   ```
2. This check runs on EVERY attempt (not just retries), so it catches WIMMount failures that happen between the first update and subsequent updates.

**Why:** This is where the user's failure originates. The CU applies, WIMMount unloads, and the .NET update call goes directly to `Add-WindowsPackageWithUnattend` → `Add-WindowsPackage` which hangs for 10 minutes. A pre-check here prevents the hang entirely.

### Task 2: Fix Test-MountState to use Test-DismReady first (CRITICAL)

**File:** `FFUDevelopment/Modules/FFU.Updates/FFU.Updates.psm1`
**Location:** Function `Test-MountState` (line 1441)

**Changes:**
Replace the current implementation that goes straight to `Get-WindowsEdition` (DISM call that hangs when WIMMount is broken) with a two-phase approach:

```powershell
function Test-MountState {
    [CmdletBinding()]
    param(
        [Parameter(Mandatory = $true)]
        [string]$Path
    )

    # First check if path exists (filesystem level, no DISM dependency)
    if (-not (Test-Path $Path)) {
        WriteLog "ERROR: Mounted image path not found: $Path"
        return $false
    }

    # Check WIMMount filter driver BEFORE attempting any DISM operation
    # This avoids the 10-minute hang that occurs when calling Get-WindowsEdition
    # against a broken WIMMount (the exact anti-pattern identified in v1.9.8 fixes)
    if (-not (Test-DismReady)) {
        WriteLog "ERROR: WIMMount filter driver is not loaded - mounted image cannot be validated via DISM"
        WriteLog "Attempting WIMMount auto-repair..."
        if (-not (Test-DismReady)) {
            WriteLog "ERROR: WIMMount auto-repair failed. Mounted image state cannot be determined."
            return $false
        }
        WriteLog "WIMMount filter driver restored. Proceeding with image validation."
    }

    # Now safe to call DISM - WIMMount is confirmed loaded
    try {
        $null = Get-WindowsEdition -Path $Path -ErrorAction Stop
        return $true
    }
    catch {
        WriteLog "ERROR: Mounted image is not accessible via DISM: $($_.Exception.Message)"
        return $false
    }
}
```

**Why:** The current `Test-MountState` uses `Get-WindowsEdition` (DISM) to check if the mount is healthy. When WIMMount is broken, this check itself hangs for 10 minutes. Adding a `Test-DismReady` fast-check (fltmc, instant) before the DISM call eliminates the hang.

### Task 3: Fix retry "refresh" call in Add-WindowsPackageWithRetry (CRITICAL)

**File:** `FFUDevelopment/Modules/FFU.Updates/FFU.Updates.psm1`
**Location:** Line 1554-1556 in `Add-WindowsPackageWithRetry`

**Changes:**
Remove or guard the "refresh" DISM call that runs before retry:
```powershell
# Current (line 1554-1556):
WriteLog "Refreshing DISM mount state before retry..."
# Clear any potentially stuck DISM operations
$null = Get-WindowsEdition -Path $Path -ErrorAction SilentlyContinue

# Replace with:
WriteLog "Refreshing DISM mount state before retry..."
# Only attempt DISM refresh if WIMMount is confirmed loaded (avoid 10-min hang)
if (Test-DismReady) {
    $null = Get-WindowsEdition -Path $Path -ErrorAction SilentlyContinue
} else {
    WriteLog "WARNING: Skipping DISM refresh - WIMMount is not loaded"
}
```

**Why:** This is another DISM-to-check-DISM anti-pattern. If the retry runs when WIMMount is broken, this line adds another 10-minute hang for no benefit.

### Task 5: Guard raw Dism.exe /Cleanup-Image call (MODERATE)

**File:** `FFUDevelopment/BuildFFUVM.ps1`
**Location:** Line 3998

**Changes:**
```powershell
# Current (line 3996-3998):
WriteLog 'Clean Up the WinSxS Folder'
WriteLog 'This can take 10+ minutes depending on how old the media is and the size of the KB. Please be patient'
Dism /Image:$WindowsPartition /Cleanup-Image /StartComponentCleanup /ResetBase | Out-Null

# Replace with:
WriteLog 'Clean Up the WinSxS Folder'
WriteLog 'This can take 10+ minutes depending on how old the media is and the size of the KB. Please be patient'
if (-not (Test-DismReady)) {
    WriteLog "WARNING: WIMMount filter driver is not loaded - skipping WinSxS cleanup"
    WriteLog "WinSxS cleanup is non-critical and can be performed on the deployed image later"
} else {
    Dism /Image:$WindowsPartition /Cleanup-Image /StartComponentCleanup /ResetBase | Out-Null
}
WriteLog 'Clean Up the WinSxS Folder completed'
```

**Why:** This raw Dism.exe call would hang if WIMMount broke during update application but the error was somehow recovered. WinSxS cleanup is non-critical — skipping it is better than a 10-minute hang.
