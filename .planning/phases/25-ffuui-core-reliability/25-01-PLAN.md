<objective>
Create centralized UI state recovery functions to ensure UI remains consistent after errors.

Purpose: Eliminate ad-hoc state reset code scattered across BuildFFUVM_UI.ps1, providing a single
function that resets all relevant controls (progress bars, buttons, flags, status text) after any
error condition. This addresses the research finding that "error handling path doesn't reset all
UI elements" causing stuck progress bars.

Output: FFUUI.Core.StateRecovery.psm1 module with Reset-FFUUIToIdle function, integrated into
BuildFFUVM_UI.ps1 error handling paths.
</objective>

  <action>
Create new module FFUUI.Core.StateRecovery.psm1 with three functions:

1. **Reset-FFUUIToIdle** - Main function to reset UI after errors
   - Parameters: -State (PSObject, mandatory), -StatusMessage (string, optional, default "Ready")
   - Reset progress bars: pbOverallProgress.Visibility = 'Collapsed', pbOverallProgress.Value = 0
   - Reset build button: btnRun.IsEnabled = true, btnRun.Content = "Build FFU"
   - Reset flags: isBuilding = false, isCleanupRunning = false
   - Update status: txtStatus.Text = StatusMessage
   - Stop poll timer if running: pollTimer.Stop()
   - Clean up messaging context if exists (call Close-FFUMessagingContext)
   - Include null checks for all controls (defensive coding)

2. **Save-FFUUIState** - Capture current state for potential recovery
   - Parameters: -State (PSObject, mandatory)
   - Returns hashtable with: isBuilding, btnRunContent, btnRunEnabled, progressValue, progressVisible, statusText
   - Used before operations that might fail

3. **Restore-FFUUIState** - Restore from saved state
   - Parameters: -State (PSObject, mandatory), -SavedState (hashtable, mandatory)
   - Applies saved values back to controls
   - For rollback scenarios

Follow PowerShell best practices: [CmdletBinding()], [OutputType()], param blocks, comment-based help.
Use WriteLog for all state changes (existing pattern in codebase).
