**Describe 'WinGetWin32Apps.json Ordering - Post-Download Reorder'** -Tag 'Unit', 'FFU.Common.Winget', 'Phase37', 'WINGET-01':

These tests directly manipulate WinGetWin32Apps.json to simulate the state after downloads complete, then verify the reorder algorithm by examining JSON content.

1. `It 'Should reorder apps to match AppList.json sequence'`:
   - Create WinGetWin32Apps.json with 3 entries in reverse order (C, B, A) with Priority 1, 2, 3
   - Create AppList.json with order A, B, C (winget source)
   - Create OrchestrationPath with the JSON
   - Call the reorder logic (by invoking the module-internal section or building a minimal test scenario)
   - **Alternative approach:** Since the reorder is inline in Get-Apps, test it by creating a helper that reads JSON, applies the algorithm, and verifies output. Use module scope invocation.
   - Verify final JSON order is A, B, C with Priority 1, 2, 3

2. `It 'Should place dependencies before parent app'`:
   - Create WinGetWin32Apps.json with entries: Parent (no DependencyFor), Dependency (DependencyFor = "Parent")
   - After reorder, Dependency should have lower priority than Parent
   - Verify Dependency.Priority < Parent.Priority

3. `It 'Should normalize architecture suffixes for matching'`:
   - Create WinGetWin32Apps.json with entry named "TestApp (x64)"
   - AppList.json has "TestApp" (no suffix)
   - Verify the entry matches and gets correct OrderKey (not pushed to end)

4. `It 'Should push unknown apps to end of order'`:
   - Create WinGetWin32Apps.json with entries: KnownApp, UnknownApp
   - AppList.json has only KnownApp
   - Verify UnknownApp gets higher priority number (sorted after KnownApp)

5. `It 'Should handle single-entry JSON without reorder'`:
   - Create WinGetWin32Apps.json with 1 entry
   - Verify no error thrown, JSON unchanged
